# 已知限制

最后更新：2026-05-01

## 平台限制

1. 当前以 Windows 为优先平台，`sleep_control` 依赖 Windows 电源能力。
2. macOS/Linux 尚未建立能力矩阵，也未验证窗口、剪贴板、电源控制等行为。

## 工具限制

1. `clipboard_history` 仅记录文本剪贴板，不包含图片、文件对象和富文本格式。
2. `batch_rename` 目前只处理目标目录第一层文件，不递归子目录。
3. `keygen_tool` 的文件哈希通过前端读取文件并传给后端，当前限制单文件最大 16 MB。
4. `sleep_now` 属于高风险动作，当前仅在前端做二次确认，尚未形成统一的权限确认中间层。

## 架构限制

1. 插件自动注册只负责“发现和调用插件”，不会自动生成高质量专用 UI。
2. 通用插件面板使用 JSON 手动输入 payload，偏开发者向，不适合复杂工具的长期主路径。
3. 日志以本地 JSONL 存储，暂未提供内置日志轮转、清理策略和空间上限控制。
4. 前端当前使用原生 ES Modules 管理状态与组件，暂未引入 React/Vue 等框架。
5. 前端工具逻辑已拆到 `web/js/tools/*`，但样式仍集中在 `app.css`，后续需要继续拆分 CSS。
